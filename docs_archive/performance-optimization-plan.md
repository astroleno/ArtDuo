# 🚀 ArtDuo 性能优化方案

## 📊 当前性能瓶颈分析

### 主要瓶颈 (按影响程度排序)
1. **LLM评分系统** - 58%时间 (45.8秒/78.5秒)
2. **搜索计划构建** - 19%时间 (15.2秒/78.5秒)  
3. **API搜索** - 15-20%时间 (10-15秒/78.5秒)

### 详细分析
- **LLM评分**: 40/47作品，每作品单独调用，串行处理
- **搜索计划**: 单次LLM调用构建搜索计划
- **API搜索**: Met + Rijks并发调用，网络延迟

## 🎯 优化目标
- **总响应时间**: 从78.5秒 → 15-20秒 (提升75%+)
- **LLM评分时间**: 从45.8秒 → 8-12秒 (提升70%+)
- **搜索计划时间**: 从15.2秒 → 3-5秒 (提升70%+)

## 🔧 具体优化方案

### 1. LLM评分系统优化 (最大收益)

#### 1.1 批量评分优化
```typescript
// 当前: 40个单独调用 = 40 × 1.2秒 = 48秒
// 优化: 4个批量调用 = 4 × 3秒 = 12秒

const batchSize = 10; // 每批次10件作品
const maxConcurrentBatches = 3; // 3个批次并发
```

#### 1.2 智能预筛选
```typescript
// 在评分前进行快速预筛选，减少需要评分的作品数量
const preFilteredArtworks = await quickPreFilter(artworks, emotion, 20);
// 从47件 → 20件，减少57%的评分工作量
```

#### 1.3 评分缓存
```typescript
// 缓存相同作品的评分结果
const cacheKey = `${artwork.id}-${emotion}`;
const cachedScore = await getCachedScore(cacheKey);
```

### 2. 搜索计划构建优化

#### 2.1 模板化搜索计划
```typescript
// 使用预定义模板 + 简单LLM调用来构建搜索计划
const template = getSearchPlanTemplate(emotion);
const customizedPlan = await quickCustomizePlan(template, userInput);
// 从15.2秒 → 3-5秒
```

#### 2.2 并行处理
```typescript
// 搜索计划构建与API可用性检查并行
const [searchPlan, apiStatus] = await Promise.all([
  buildSearchPlan(emotion, userInput),
  checkAPIStatus()
]);
```

### 3. API搜索优化

#### 3.1 连接池优化
