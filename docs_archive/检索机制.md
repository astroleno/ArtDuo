# 结论（删掉全网搜索）

只做 Met + Rijks 的官方 API 已能覆盖你当前“无状态 + 个性化沉浸式策展”的需求：

* **Met**：无需 API Key，官方限速建议 80 RPS；提供 `/search`（多维过滤）→ `object` 详情全字段（含大图与版权）。([大都会艺术博物馆API][1])
* **Rijks**：新 **Search API**（beta）无需 Key，按“Linked Art Search”返回 **LOD 标识**；随后用 **HTTP 持久标识解析**拿到结构化元数据，再经 **IIIF** 拿到图片。旧 REST 已标注 **Deprecated**，仅做兜底。([国立博物馆数据服务][2])

# 基于文档的关键点（你实现时会用到）

* **Met 搜索参数**（示例）：`q`、`title`、`tags`、`artistOrCulture`、`departmentId`、`isHighlight`、`hasImages`、`medium`、`geoLocation`、`dateBegin/dateEnd`；先 `/search` 拿 `objectIDs`，再逐个 `/objects/{id}` 拉详情。无需 Key。([大都会艺术博物馆API][1])
* **Met 速率与访问**：官方明确“无需注册/Key，限制 80 req/s”。([大都会艺术博物馆API][1])
* **Rijks Search API**：`GET https://data.rijksmuseum.nl/search/collection`，参数含 `title/creator/type/material/creationDate/description/aboutActor` 与 `imageAvailable=true/false`；分页用 `pageToken`，每页 100 条；搜索结果是 LOD ID（如 `https://id.rijksmuseum.nl/…`）。 ([国立博物馆数据服务][2])
* **Rijks HTTP 解析**：把 `id.rijksmuseum.nl/<int>` **重定向**到可协商的元数据表示（Linked Art、EDM 等）；支持通过 **HTTP 头或查询参数**做内容协商。([国立博物馆数据服务][3])
* **Rijks 图像**：经 **IIIF Image API（Micrio）** 拿 `info.json` 与派生图（裁剪、缩放、旋转等），也可取 **IIIF Presentation** 的 `manifest`。([国立博物馆数据服务][4])

# 优化后的“纯 API 聚合”流水线

适合部署在 Vercel Functions/Edge，**无全网搜索**。

1. **意图-查询规划（LLM 服务端）**
   将用户输入转为结构化检索计划：
   `{ keywords[], filters: {dateRange, medium, geo, creator, type, onView, highlight, hasImages/imageAvailable}, sources: ["met","rijks"] }`
   然后把 filters 映射到各馆 API 的原生参数（见下文映射表）。

2. **并发检索（Met + Rijks）**

* **Met**：
  `GET /public/collection/v1/search`
  典型组合：`q` + `hasImages=true` +（可选）`title=true|artistOrCulture=true|medium=…|geoLocation=…|dateBegin/dateEnd` → 拿 `objectIDs` → 批量 `GET /objects/{id}`。([大都会艺术博物馆API][1])
* **Rijks**：
  `GET https://data.rijksmuseum.nl/search/collection?imageAvailable=true&title=…&creator=…&type=…&material=…&creationDate=…` → 得到 **LOD IDs**（每页 100，`next.id` 继续翻页）→ 逐个 **HTTP 解析**成 Linked Art/EDM JSON（按你需要的 profile 协商）。([国立博物馆数据服务][2])

3. **取图与许可**

* **Met**：直接用对象详情里的 `primaryImage/primaryImageSmall` 与 `isPublicDomain`。([大都会艺术博物馆API][1])
* **Rijks**：从解析后的元数据里定位到数字对象的 **IIIF 标识**，再调用 **Micrio IIIF** 的 `…/info.json` 与具体派生图 URL。([国立博物馆数据服务][4])

4. **统一字段与清洗**
   落一层统一 Schema（建议）：
   `{ id, source, title, maker, datingText, dateBegin, dateEnd, type, medium, materials[], place[], onView?, isHighlight?, image.url, image.iiifInfo?, rights, license, permalink }`

* Met 字段直接映射（如 `artistDisplayName`, `objectDate`, `objectBeginDate`, `objectEndDate`, `medium`, `country/city`, `isOnView`, `isHighlight`, `isPublicDomain` 等）。([大都会艺术博物馆API][1])
* Rijks 从 Linked Art/EDM 中取 `title/creator/timeSpan/materials` 等，再补 IIIF 图像与许可字段。([国立博物馆数据服务][3])

5. **去重与排序**

* 去重：`title+maker` 近似 + 年份容忍（±2–5 年）→ 优先保留“有 IIIF/大图/开放许可”的条目。
* 排序：`相关性(LLM)` × `图像质量(是否有大图/IIIF)` × `许可友好度(公共领域/开放许可)` × `权威度(Highlight/OnView/部门)`。

6. **流式返回（前端体验）**
   先返回前 6–9 个“卡片摘要”（标题、作者、年代、首图、来源），随后补齐长说明与更多图；任一源失败不影响另一源回传。

## 参数映射表（便于开发）

* **has image**：Met → `hasImages=true`；Rijks → `imageAvailable=true`。([大都会艺术博物馆API][1])
* **标题/关键词**：Met → `q` + 可选 `title=true`；Rijks → `title=…` 或 `description=…`。([大都会艺术博物馆API][1])
* **作者**：Met → `artistOrCulture=true` + `q=作者名`；Rijks → `creator=…`（可多次）。([大都会艺术博物馆API][1])
* **年代**：Met → `dateBegin/dateEnd`；Rijks → `creationDate=YYYY` 或通配 `16??`。([大都会艺术博物馆API][1])
* **类型/材质**：Met → `medium=…`；Rijks → `type=…`、`material=…`、`technique=…`。([大都会艺术博物馆API][1])
* **地理**：Met → `geoLocation=…`；Rijks（若需）从描述/地点字段匹配后用 LLM 侧重打分。([大都会艺术博物馆API][1])
* **亮点/在展**：Met → `isHighlight=true`、`isOnView=true`；Rijks暂无直接等价，靠描述与馆方标注字段间接体现。([大都会艺术博物馆API][1])

## 性能与稳定性建议

* **并发批**：Met `objects/{id}` 建议 8–16 并发；Rijks Search 每页 100 条，按 `next.id` 逐页拉，解析时同样 8–16 并发。([国立博物馆数据服务][2])
* **速率控制**：遵守 Met 80 RPS 建议；Rijks Search 未写硬性上限，但“beta”状态更应保守。([大都会艺术博物馆API][1])
* **缓存**：

  * 查询结果：按 `keywords+filters+source` 短 TTL（1–6h）。
  * 详情：Met 对象可长 TTL；Rijks 通过 IIIF `info.json` 缓存宽限。
  * 增量更新：Met 可用 `objects?metadataDate=YYYY-MM-DD` 扫描变更。([大都会艺术博物馆API][1])
* **失败降级**：任一源超时就先返回已就绪卡片；Rijks 解析失败时保留 LOD 标识与来源链接，稍后补全。

## 何时才考虑“旧 REST（Rijks）或全网搜索”

* 只有当 **Rijks Search + HTTP** 无法覆盖你要的字段，或临时需要 `imgonly` 旧语义时，才短期兜底到 **REST（Deprecated）**；但新 Search 已有 `imageAvailable`，优先用新接口。([国立博物馆数据服务][2])
* 全网搜索（Google/Bing/SerpAPI）可完全移除；若未来接更多馆（AIC、Cleveland、Smithsonian 等）再评估是否增加 **Europeana/DPLA** 之类聚合源。
