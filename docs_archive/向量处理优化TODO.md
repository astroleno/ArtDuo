# ArtDuo 向量处理优化 TODO

## 📋 项目概述

基于现有9000件艺术作品数据，实施本地化向量处理方案，实现**毫秒级语义检索**，将策展速度从15-25秒优化到3-5秒，API调用量减少90%。

## 🎯 核心目标

- **速度提升**: 策展时间从15-25秒 → 3-5秒
- **成本降低**: API调用减少90% (从50-100次 → 5-15次)
- **准确度提升**: 通过向量语义检索 + 情绪预分类
- **完全本地化**: 无外部向量数据库依赖

## 📊 当前状态分析

### 数据规模
- **总作品数**: 9000件 (Met Museum数据)
- **情绪分类**: 66个情绪类别，已按情绪预分类
- **数据完整性**: 约231件作品缺少描述，需要处理
- **存储位置**: `data/met/artworks/` (66个JSON文件)

### 现有技术栈
- **前端**: Next.js 15 + TypeScript
- **LLM**: 智谱AI GLM-4.5
- **评分系统**: `llm-judge-ultra-optimized.ts`
- **缓存**: 内存缓存 + IndexedDB
- **部署**: Vercel (静态托管)

## 🚨 风险评估和应对

### 高风险项
- 🔴 **数据质量**: 231件无描述作品影响检索质量
  - **应对**: 数据清洗 + 智能补全 + 降权处理
- 🔴 **内存占用**: 向量索引可能占用较多内存
  - **应对**: 按需加载 + 压缩存储 + 边缘计算

### 中风险项
- 🟡 **模型兼容性**: 不同环境下的模型加载
  - **应对**: 多环境测试 + 降级方案
- 🟡 **索引更新**: 数据变更时的索引维护
  - **应对**: 增量更新 + 版本控制

### 低风险项
- 🟢 **性能提升**: 向量检索速度优势明显
- 🟢 **成本控制**: 大幅减少LLM API调用
