- 不用向量库的语义匹配思路
      - 最直接的是在“轻量嵌入 + 本地度量”模式下自己算相似度：用现成的句向量模型（比如 all-MiniLM-
  L6-v2）生成嵌入，把结果序列化到磁盘（JSON/Parquet/NumPy 都行），查询时在内存里做余弦或点积。数
  据量在一万级，单机用 ANN 库（annoy、hnswlib）就能秒级检索，无需部署完整向量数据库。
      - 如果完全不想算嵌入，也可以用 BM25 / TF-IDF 做文本检索，再把情绪权重和关键词映射组合到排序
  函数里；不过语义泛化会弱很多，建议至少用轻量嵌入。
      - 另一条路是“LLM reranker”：先靠关键词或 tags 做粗召回，再用 LLM 输入情绪+作品文本，让模型
  打分排序。优点是不需要大量预处理，缺点是成本和时延高，而且每次查询都得多轮 API 调用。
  - 是否删除无描述的作品
      - 全量 8824 件里还有 ~231 件没有简介，大多是 Met 页面本来就没有 label。它们通常仍有标题、标
  签、媒介等信息，对多样化策展或图像展示仍有价值。若直接删掉，会影响情绪覆盖，也可能错失一些视觉
  素材。
      - 更好的做法是打标而不是删除：在索引或排序时给“无描述”作品较低权重，或在前端提醒“暂无释
  文”。也可考虑用已有字段（如 credit line、艺术家传记、tags）拼合一段 fallback 描述，或让 LLM 根
  据这些结构化信息生成一个摘要。
      - 真正要清理时，可以先查验证报告的 missingDescriptionIDs；对确实无释文的条目，可人工确认后
  保留、替换或补写，而不是在数据阶段完全删除。
