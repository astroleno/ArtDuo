# DeepSeek V4 Flash 多文本质量 Eval：v3.1 定点迭代

## 最终决策

v3.1 的定点迭代已经完成，但不整体替换上一版推荐：

- 混合情绪、愤怒、隐私：继续使用 `source-isolated-v1`。
- 中性情绪：采用 v3.1 的独立短契约与“不新增现场动作”规则。
- 作品介绍：继续使用 `source-isolated-v1`，本轮不再加长。
- 前言/结语的质量优先路径：继续使用完整 `source-isolated-v3`。
- v3.1 framing 仅作为低成本候选；确定性语义 guard 失败时回退完整 v3，不做自由扩写式重写。
- `guarded2` 条件重写不作为默认路径。

本轮又执行 218 次 DeepSeek V4 Flash 流式请求：160 次 v3.1 单次提示词试验、46 次条件修订、12 次夜景字段专项回归；全部 HTTP 200。加上上一报告的 104 次，累计 DeepSeek 流式探针为 322 次。

## v3.1 单次路径

正式 8 轮包含中性情绪 8 条与 framing 32 条。两位独立评估员继续对照 Codex Sol max 与 Kimi K3 max 双 golden 逐条盲评。

| 指标 | Evaluator A | Evaluator B | 双评委均值 |
|---|---:|---:|---:|
| 全量语义分 | 17.975 | 18.825 | 18.400 |
| 中性情绪 | 18.625 | 19.125 | **18.875** |
| framing | 17.8125 | 18.750 | **18.281** |
| 严重错误 | 3/40 | 3/40 | — |

完整 v3 framing 的双评委均值为 19.00；压缩后的 v3.1 framing 下降约 0.72 分。损失集中在夜景结语的字段偷换与故事化引导，其他三个 framing case 仍接近 19 分。

技术指标：

| 范围 | TTFT p50 | TTFT p95 | 总时间 p50 | 总时间 p95 | 平均输入 tokens | 平均输出 tokens |
|---|---:|---:|---:|---:|---:|---:|
| v3.1 全量 | 649 ms | 888 ms | 1392 ms | 1754 ms | 463.0 | 89.3 |
| 中性情绪 | 587 ms | 879 ms | 1107 ms | 1282 ms | 272.0 | 43.8 |
| framing | 639 ms | 918 ms | 1466 ms | 1769 ms | 510.8 | 100.7 |

v3.1 framing 相比完整 v3 的 693.5 input tokens 节省约 26%。这项压缩没有全面破坏事实边界，但降低了文本功能和弱 case 的稳定性，因此不应成为质量优先的默认路由。

## 中性情绪契约

中性案例不再复用其他情感任务的 55–100 字回复下限。新契约为：

- `emotion_read`：10–30 字
- `response`：10–40 字
- 不分析、不追问，不新增陪伴动作、物品、服务提议或餐后安排

八轮双评委均分 18.875，无严重错误。该改动应保留。它解决的是契约与用户“简短、不分析”要求之间的冲突，不是通过增加心理话术来补字数。

## framing 压缩与长度

v3.1 使用了精确字数契约、逐句事实槽位和一个短示例，但 DeepSeek 仍系统性少写约 5–35 个中文字。按精确范围重新计分后：

- single-pass hard pass：13/40（32.5%）
- 其中 emotion：7/8（87.5%）
- framing：6/32（18.75%）

这说明继续在单条提示词里强调“至少多少字”不能可靠解决中文字符计数。语义合格但短 3–6 字的文本不应被自由重写成更长的幻觉文本。

## 条件重写实验

对失败项最多执行两轮条件重写后：

| 指标 | single-pass | guarded2 |
|---|---:|---:|
| 双评委语义均值 | 18.400 | 18.600 |
| hard pass | 32.5% | 65.0% |
| 平均输入 tokens | 463.0 | 985.4 |
| 平均输出 tokens | 89.3 | 213.6 |
| 总时间中位数 | 1.392 s | 3.210 s |
| 总时间 p95 | 1.754 s | 5.348 s |

guarded2 主要改善格式，语义只增加 0.20 分。两位评估员还发现，部分被选择的修订会把“12条记录”改成“12件”、补出使用经历或新的解释。成本翻倍、延迟翻倍，却没有回到完整 v3 的 19.00 分，因此不采用。

条件修订只应保留给 JSON 不可解析或字段缺失等结构失败；单纯长度不足不触发整段自由重写。

## 夜景字段补丁

旧 v3.1 夜景弱 case 会把“照片中人物身份未记录”偷换成“拍摄者身份未记录”。补丁将句槽固定为：

> 资料未提供照片中人物的身份，也未提供拍摄动机。

并把结尾限制为观众自行观看。12 轮专项结果：

- 人物身份字段偷换：0/12
- 背后故事/待探寻叙事：0/12
- 双评委均分：18.458/20
- 严重错误：Evaluator A 0/12，Evaluator B 1/12
- TTFT 中位数：505 ms
- 总时间中位数：1178 ms
- 输入 tokens：519

唯一争议样本增加了“光影、夜色、时间痕迹”。现有确定性 `semantic_guard` 能捕获该样本及另一个轻度视觉引导样本，因此推荐策略是：命中 guard 时直接回退完整 v3，而不是自动扩写。

## 是否继续迭代

当前不建议继续堆叠 framing 提示词。原因：

1. 完整 v3 已达到双评委 19.00/20、严重错误率 5%。
2. v3.1 成功降低 tokens，但语义略降，且字数遵循没有达到 90% 目标。
3. 条件自由重写的成本明显高于语义收益。
4. 夜景字段偷换已通过窄规则消除。

下一阶段应是确定性校验与路由，而不是继续写更长的 system prompt：

1. 中性情绪使用 v3.1 短契约。
2. framing 默认完整 v3。
3. 若需要低成本模式，先跑 v3.1；命中字段或语义 guard 时回退完整 v3。
4. 严格字数若是产品硬要求，应采用受控的局部补句或人工模板，不采用整段自由重写。
