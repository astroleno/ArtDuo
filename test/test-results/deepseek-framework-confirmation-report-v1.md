# DeepSeek V4 Flash 新框架确认 Eval

## 判定

**暂不确认整套新框架。** 预先约定的 gate 结果为 `framework=hold`：通用任务路由 v5 在未见集上的语义质量明显提高，但 TTFT 没有达到至少 10% 的改善；前言/结语拆成两个并行请求虽然更快，却显著损伤质量并增加严重错误。

本轮应确认的是更窄的方向，而不是整包架构：情感理解、作品介绍和大部分策展分析使用 v5；前言与结语保留 v3 的事实账本思路，并继续在一次 combined 请求里共同生成。生产代码本轮未修改。

本轮新增 **188 次** DeepSeek 流式请求：全部 HTTP 200、全部收到并解析约定 JSON、thinking 字符均为 0。另使用 Codex Sol max 生成 16 个未见 case 的参考答案，由两位独立评估员盲评，不按参考答案措辞相似度打分。

## 未见集：v3 与通用任务路由 v5

16 个新 case 覆盖情感理解、作品介绍、前言、结语和策展分析；每个 variant 每个 case 跑四轮，共 128 次流式请求。

| 指标 | source-isolated-v3 | generic-task-routed-v5 | v5 变化 |
|---|---:|---:|---:|
| 样本 | 64 | 64 | — |
| 平均输入 tokens | 395.00 | 328.31 | **-16.9%** |
| 平均输出 tokens | 103.53 | 100.25 | -3.2% |
| TTFT 中位数 | 475.5 ms | 476.5 ms | **+0.2%** |
| 总时间中位数 | 1451 ms | 1422.5 ms | -2.0% |
| JSON 可用率 | 100% | 100% | 持平 |
| deterministic hard pass | 78.1% | 68.8% | -9.4pp |
| 核心证据覆盖 | 89.3% | 94.4% | +5.2pp |
| 双评估员均分 /20 | **16.953** | **18.141** | **+1.187** |
| 双评估员严重错误率 | 33.6% | 12.5% | **-21.1pp** |

v5 减少了输入，语义表现也更好，但没有复现上一轮 task-routed-v4 的 TTFT 优势；本批 TTFT 实际慢 1 ms。因此“分开提示词一定更快”不能成立，至少当前 v5 不满足预注册的 10% TTFT gate。

### 双评估员按任务结论

| 任务 | v3 | v5 | v5 − v3 | 严重错误率 v3 → v5 | 结论 |
|---|---:|---:|---:|---:|---|
| 情感理解 | 18.031 | 19.031 | **+1.000** | 21.9% → 3.1% | 用 v5 |
| 作品介绍 | 18.063 | 19.844 | **+1.781** | 18.8% → 0% | 用 v5 |
| 展览前言 | 19.250 | 17.063 | **-2.188** | 0% → 18.8% | 保留 v3 |
| 展览结语 | 18.813 | 14.688 | **-4.125** | 0% → 50.0% | 保留 v3 |
| 策展分析 | 12.688 | 17.813 | **+5.125** | 93.8% → 12.5% | 用 v5，但补无障碍 profile |

两位评估员对总体方向一致：v5 在情感理解、作品介绍、策展分析上更好，在前言和结语上回退。主要风险是：

- 混合情绪偶尔仍会被命名或建立因果，但频率已明显下降。
- 作品介绍在四类新证据状态上最稳定，v5 双评均分 19.844，未标记严重错误。
- 前言容易把记录痕迹升格为历史意义；结语容易把“只确认一份完整转写”改写成“其余内容缺失/无法还原”。
- 策展分析改善最大，但两位评估员对“跨代可访问性”case 存在分歧；其中一位认为四轮都推断了注意力或理解能力。这类输入应单设“禁止能力推断”的 profile。

## 前言与结语：combined 与并行 split

4 个同源材料包各跑五轮。combined 为 20 次单请求；split 为 20 组、每组两个并行请求，共 40 次请求。

| 指标 | combined | split | split 变化 |
|---|---:|---:|---:|
| 策略样本 | 20 | 20 | — |
| 实际请求 | 20 | 40 | +100% |
| 平均输入 tokens | 279.5 | 636.0 | **+127.5%** |
| 平均输出 tokens | 186.8 | 216.9 | +16.1% |
| 首段 TTFT 中位数 | 659 ms | 422 ms | **-36.0%** |
| 两段全部完成中位数 | 2373.5 ms | 1556.5 ms | **-34.4%** |
| JSON 可用率 | 100% | 100% | 持平 |
| 双评估员均分 /20 | **16.275** | **14.375** | **-1.900** |
| 双评估员严重错误率 | 37.5% | 67.5% | **+30.0pp** |

split 的速度收益真实且稳定，但代价不是只有重复输入：两个请求更容易各自补故事、原因和象征，再在两段中叠加。两位评估员均判定 combined 更好。因此不确认“前言/结语拆开并行”作为默认架构。

combined 本身也还不够稳：37.5% 的双评严重错误率说明它只是相对胜出，并非可直接上线。下一轮应给 combined 增加共同事实护栏和双段联合校验，重点禁止从刻痕、缺页、空白、目录条目推导航行故事、等待情绪、传播史或观众体验。

## 预注册 gate

| Gate | 要求 | 实测 | 结果 |
|---|---|---:|---|
| 路由语义质量 | v5 − v3 ≥ -0.25 | +1.187 | 通过 |
| 路由严重错误 | 不增加 | -21.1pp | 通过 |
| 路由解析率 | ≥99% | 100% | 通过 |
| 路由 TTFT | 改善 ≥10% | **-0.2%** | **未通过** |
| split 语义质量 | split − combined ≥ -0.25 | **-1.900** | **未通过** |
| split 严重错误 | 不增加 | **+30.0pp** | **未通过** |
| split 全完成时间 | 改善 ≥5% | +34.4% | 通过 |

## 下一版应确认的候选架构

1. `emotion_response`：v5 通用路由 + 明确情绪白名单。
2. `artwork_intro`：v5 通用路由 + 证据状态 profile。
3. `curation_analysis`：v5 通用路由，但跨代/无障碍输入使用专门的 no-capability-inference profile。
4. `exhibition_preface` 与 `exhibition_closing`：职责仍分开定义，执行上保持一次 combined 请求，共享不可变事实表与禁用语义清单。
5. 前言/结语通过双段联合校验后，再对新未见集复测；只有严重错误显著下降，才冻结为生产框架。

所以当前答案是：**提示词模块化方向已经被支持，但新的执行框架还不应该确认。还需要一轮针对前言/结语和无障碍策展分析的窄迭代。**
