# ArtDuo 单实例发布与恢复

本文件是发布操作方案。2026-10-25 已完成目标机隔离、双层代理和持久数据重启验收，并在用户确认“切换公网测试版”后启用两个 `.me` 域名的 `/ArtDuo`。公网浏览器、真实策展、按需讲解、普通分享及手写卡下载与恢复已通过本轮检查；首画 8 秒与深度图实际观感仍未完成最终验收。实际主机、路径见 [双域名部署](artduo-dual-domain.md)，最终证据见 [公网测试版验收](../verification/artduo-public-beta-2026-10-25.md)。

## 部署形态

沿用 Node.js 22 或更高版本、pnpm 8.15.1、Next.js 和本机多语言 E5 语义模型。只启动一个应用实例；额度账本和并发锁使用本机持久磁盘，不支持多台主机或多个独立容器共享额度。构建目录与源码版本配对，不能在正在提供服务的同一目录内覆盖构建。

准备当前工作区发布内容、`pnpm-lock.yaml`、`data/releases` 及所引用的旧版本图片、`public` 中三个背景和灯光素材、视觉证据与署名修正数据、本地语义权重 `.cache/artduo-models`。保留完整发布资源和清单，不只复制 Next.js 页面包。原图校验缓存 `.cache/artduo-public-images` 可作为额外缓存；公开观展使用持久目录内已校验的 WebP 预览，不依赖临时原图缓存。

使用 [环境样例](../../deploy/artduo.env.example) 配置主机。`ARTDUO_STATE_DIR` 必须是应用用户可读写的持久绝对路径，并位于所有静态公开目录之外。私有目录包含 `curations`、`explanations`、`artwork-previews`、`request-policy.json` 和不含密钥、原始输入、原始 IP 的调用日志。目录设为 0700，记录为 0600；不要通过静态服务器暴露它。

## 素材与应用检查

在发布工作区使用真实环境执行以下步骤。素材准备只访问当前发布清单的已核对 URL，不新增作品；最多两个不同来源主机并行下载，同一主机始终串行，避免排队耗掉传输超时。逐张核对字节数与原图 SHA256，再生成最长边 1600px、保留完整比例的 WebP。源指纹与预览自身指纹分开保存。失败立即记录，重新运行会复用成功的预览。不会为了预览把所有原图永久复制一份。

```sh
pnpm install --frozen-lockfile
pnpm release:prepare-media
pnpm release:check -- --warm
pnpm test
pnpm typecheck
pnpm build
pnpm audit --prod --registry=https://registry.npmjs.org
```

正式检查要求每件可展作品均有有效的持久预览，缺少任何一张都会失败。`--local` 只验证本机并报告缺口，不能代替正式检查；`--offline` 另要求原图都在本机，适用于完全离线交付。真实原图在用户近看时按需获取、核验，预览持续可见；上游不可用仍可能影响原图近看。

先绑定 `127.0.0.1` 启动 Next.js，由 HTTPS 反向代理对外服务。代理必须覆盖而非追加 `x-real-ip`，并限制请求体和连接数；应用端口不能直接开放公网。必须由选定主机上的实际代理验证这个边界，不能仅凭传入一个可伪造请求头认定安全。

下面是单层代理的通用示例。本次已确认的腾讯与阿里两层代理，应使用 [双域名部署](artduo-dual-domain.md) 中的配置，不能用本例覆盖现有站点：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto https;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_read_timeout 65s;
    client_max_body_size 16k;
}
```

检查 `/api/health` 为 200，四项 readiness 为 true。实际走 HTTPS 入口完成一次策展、首画、下一组背景、讲解、分享回放；确认 SSE 未被代理缓冲。每日请求上限与 Token 预留上限覆盖意图、导览、详情三个付费入口。Token 账本使用输入 UTF-8 字节数加输出上限保守预留，不冒充模型实际计费用量。额度按 UTC 日重置，模型调用失败仍占本日已保留额度。

## 重启与回滚演练

1. 保存一条已完成展览的 URL、画作顺序、分组背景、完整导览和已生成讲解，并记录调用次数。
2. 停止应用，保留同一持久卷与同一发布资源。重启后打开原链接，核对作品、分组、文案、讲解；完整缓存回放不得再次生成。部分文案仅在冷却结束后补缺，成功段不重写。
3. 确认每日额度、访客限频与模型并发占用的恢复规则仍有效。异常退出留下的占用会到期；坏账本会阻止新增付费请求，不清空账本来恢复额度。
4. 发布前保留前一版源码、锁文件、构建和只读持久卷备份。回滚时切回上一版目录及其兼容数据，不能只替换脚本或删除当前额度账本。完成原链接及健康检查后才恢复入口流量。

先在目标主机的隔离端口演练上述流程，再由用户确认正式上线。本地手机尺寸模拟、模型小样本和本机反向代理演练，均不能替代目标主机、真实移动网络或实体手机验收。
