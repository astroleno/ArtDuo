# 首次进入展览提速

用户已批准本轮性能优化、自测、commit / push 与腾讯云发布；保留现有首页和沉浸体验。在当前架构内改善入口交付，不增加接口、改变模型、缩减作品或更改视觉设计。

## 调查与设计

- 旧入口使用 `location.assign`，策展完成后服务端重定向到同一已存展览，再构建与交付一次页面。模型准备已在启动时完成；导览生成已经异步，不应改成阻塞首画。
- 首份新查询的提交到 snapshot 为 8184ms；服务端该次意图请求 3666ms。首次可见画面样本因测试脚本跨文档失效而无效，不作为基线；旧报告的 32s 不是当前实测。
- `ExperienceEntryClient` 改用 Next 导航，沿用当前的退出状态和表单；提交时并行预载展厅客户端模块，不提前提交用户正在输入的内容。
- `ImmersivePage` 对刚生成的展览直接返回当前快照，通过 `canonicalHref` 将已保存的展览身份交给 `ExperienceRouteClient`。客户端原位更新地址，不重新请求策展。已有展览的纠错、旧配方、错误状态保留当前服务器行为。原生 GET 继续可用；无 JavaScript 通过已生成展览的地址继续原有跳转路径。
- 返回首页需要恢复刚才的输入；保留现有 history / 浮层返回控制器。首页居中、透明底线、明暗切换、五秒问句及液态玻璃不变。
- 缓存页面从地址恢复当前作品与顺序，不让第一次响应里的前言覆盖 Forward；只接受同展览、版本、愿望的地址。客户端导航继续沿用提交计时，并消费跨文档后备标记，避免将后续刷新误计为一次长提交。
- 不修改策展意图格式、检索模型、作品顺序、预览质量、景深 / 光照、十八件雕塑和 50% 偶遇规则；不以回放缓存代替首次新策展测量。

## 验证与交付

1. 固定浏览器环境和测量口径，分别记录新策展与已存展览。收集提交、snapshot、进入展厅和图片实际解码 / 可见 / 可操作时间；单列前言阅读或测试操作等待，不算成系统加载。
2. 用真实渲染检查桌面和 390×844：首页未变、提交防重、原句返回、新旧地址刷新恢复、阅读 / 近看 Back、原生 GET 与错误恢复。
3. 对改动逻辑运行有意义的回归、全项目测试、类型检查和生产构建。模型与额度约束保留；真实模型调用仅用于本轮有限样本。
4. 沿用现有分支、腾讯独立候选和两个域名，候选先构建 / 回归 / 就绪检查，再一致备份和原子切换；旧发布与持久状态保留。完成双域名实际验证、临时目录清理并提交发布记录。

首画 8s 仍是既有目标；有限样本的改善不能被写成所有查询、网络或实体手机的时延保证。
