# 画作整理、选画相关性与沉浸体验续作

日期：2026-10-06（Asia/Shanghai）

用户在核对当前缺口后要求继续处理“画选对、数据补齐，再围绕真实画作打磨空间和切换体验”，并明确要求 commit、push。本轮复用现有工作区与 `codex/artduo-v2-vector-smoke` 分支，由主线程执行。

## 范围与架构

沿用 Next 应用、版本化本地馆藏、现有 `ArtworkRecord`、检索结果与 `ExhibitionSnapshot` 接口。本轮的选画修正覆盖早期体验接入计划中“不调整排序”的限制；不引入在线模型检索、第二套应用或新会话协议。

| 模块 | 本轮职责 | 保持的接口 |
| --- | --- | --- |
| pipeline / 数据候选目录 | 保存馆方原始记录、获取时间与逐条出处；清理采集评分文字；补充经典平面画作与具体题材标签；以既有构建器生成新版本 | `ArtworkRecord` 与 metadata / search / media / embedding 分片 |
| corpus / web 检索 | 区分当前情绪、观看愿望、明确题材及排除条件；在截取最终作品前执行约束；具体题材证据优先于泛化情绪别名 | `searchReleaseCatalog(catalog, query, options)` 的调用及返回结构 |
| 情绪协商 / 场景路线 | 让实际入选作品与阶段对应，拒绝的作品不能经兜底重新进入；保留用户明确的观看方向 | `GrowthForm`、既有路线接口 |
| experience 表现层 | 校正画作、画框、墙面和展签的共同空间关系；连续切换时减少整个展厅重置感；改进鼠标移动的渲染开销和手机观看 | `ExperienceUnit`、URL 恢复、详情与分享接口 |

新数据先构建到候选 / 预览目录并核验，再以新的不可变版本接入；不覆盖 `2026-04-25-curation-b`。旧版本链接继续可访问。新增来源使用已有 `met` / `custom` 枚举，实际机构身份与权利凭据放在可追溯的旁挂记录，不能将其他机构冒记为 Met。

## 已确认的技术证据

- 当前查询和馆藏向量都为 `local-hash-embedding-v1`，没有模型维度混用；问题包括中文口语覆盖不足、情绪别名泛化与原始评分文字污染。
- 蒸汽船火灾版画被标为 melancholy，标题与检索文案重复相同词；现有检索未区分“疲惫想休息”与“希望看悲剧题材”。
- 情绪协商存在全部拒绝后回退到原候选的分支；最终画廊仍直接消费检索结果，约束必须落实到实际选集。
- Room 在每次鼠标移动时更新 React 状态；Walk 以作品 ID 重建整个房间，背景、控制与画作同时进场。
- 馆藏媒体暂无正式深度图。视差相关能力必须使用有来源、有对应底图的资源；不得将简单亮度估算宣称为真实深度。

## 数据来源与处理规则

优先使用 Met 官方 API / 藏品页；按题材缺口可补充芝加哥艺术博物馆官方 API / IIIF。只接入明确标为公共领域且有可验证图像的新增作品。保留官方原名、作者归属、年代与原始题材；中文检索词、视觉概括、情绪判断单独注明为整理结果，不伪装为馆方原文。

Met 文档已更新搜索为分页 `/v1.1/search`；AIC 小规模获取遵循官方每秒不超过一次、单线程的要求。此轮不调用付费模型，不做全馆抓取，也不补造无关联的古籍引文。新作品数量由真实题材覆盖决定，不以重复题材或不合格图像凑数。

资料：[Met API](https://metmuseum.github.io/)、[AIC API](https://api.artic.edu/docs/)。

图像核验补充：AIC API 元数据可读，但馆方图片端点返回 403。采用 Commons 的公开绘画副本，逐条比对 AIC 藏品编号并保留文件页、许可、实际下载地址与散列；未通过解码的候选不能入版。为避免上游限流破坏正式观看，将已核验新作的等比预览图和大图打包进版本目录，沿用现有媒体字段及图片代理接口；构建器严格校验相对路径、文件存在性及符号链接边界。外部图片仍走原路径，不改变旧版数据。

## 验收

1. 当前画作类型筛选继续成立；新数据通过契约解析、来源 / 权利 / 图像可读性 / 稳定 ID / 重复项核验，清理后的公开文案不含内部评分说明。
2. 检查疲惫、低落求缓和、明亮活力、静物 / 建筑题材、山水 / 树木 / 水面、中文夹杂英文六组完整选集；另检查明确想看战争 / 死亡、否定森林而想看海、作品名与作者查询。记录具体作品及入选证据，不只看分数或首图。
3. 想安静、缓和时不因负面情绪词优先推荐明显灾难、暴力或死亡场景；用户明确要求这些题材时仍可得到相应绘画。明确排除条件不能被补足件数的逻辑覆盖，无可靠匹配时允许短结果或空结果。
4. 桌面与 320 / 390 px、横屏核对真实绘画比例、画框与墙面的关系、展签与导航可达性；前后切换、放大、详情返回、结语和分享正常，减弱动效与媒体失败有可用退路。
5. 完成相关单测、类型检查、构建及浏览器回归；最后冻结源码再执行验证，避免开发服务热更新干扰结果。保留失败记录，不能用部分通过冒充完整通过。
6. 核对任务文件与已有工作树后提交并推送当前分支；不自动合并或部署。默认呈现切换仍遵循原有验收门槛，真实设备、音频授权等无法凭自动化替代的事项如实记录。
