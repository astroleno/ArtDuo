## 应保留的部分

1. **入口的注意力预算合理。** 稳定态 [E22 手机浅色](artduo-frontend-2026-10-28/evidence/entry-mobile-light-stable.png)、E01/E02/E05 显示一个问句、一个输入、一个主动作，背景柔和。空提交的 [E03](artduo-frontend-2026-10-28/evidence/entry-empty-error.png) 将错误留在输入下方。源码 `threshold.tsx:57–80` 保留输入聚焦时暂停翻牌、就地反馈与主动作。入口无需再加说明层或输入框容器。
2. **作品、展签、阅读的层级可以被理解。** [E10 桌面展厅](artduo-frontend-2026-10-28/evidence/walk-desktop-idle.png)、[E12 手机展厅](artduo-frontend-2026-10-28/evidence/walk-mobile-arrival.png) 以作品为主体；[E14 阅读层](artduo-frontend-2026-10-28/evidence/reading-mobile.png) 仍保留参考图像。纸质展签与操作按钮的材质有区别，玻璃控件没有替代作品的视觉地位。
3. **文字与位置稳定是沉浸感的重要基础。** 源码 `use-stable-narrative.ts:6–16` 在文字可读后保持本次显示；`plaque.tsx:9–14` 固定打开时的阅读文本。实际从资料页返回，恢复了同一 `curationId` 和 `artic-16487`，见 E15–E18 记录。应保留这种位置连续性。
4. **结语有明确的停顿。** [E19b 桌面](artduo-frontend-2026-10-28/evidence/closing-desktop-stable.png) 与 [E20b 手机](artduo-frontend-2026-10-28/evidence/closing-mobile-stable.png) 将最后一幅作品、短句、回看/保存分开，未在主视觉中加入路线算法或评分。手写卡作为可选动作，并在打开后明确确认文字与发送范围（E08；`handwritten-keepsake.tsx:168–186`）。
5. **人民题材与雕塑侧厅在视觉上能够共存。** [E23 手机](artduo-frontend-2026-10-28/evidence/sculpture-calais-mobile-preview.png) 与 [E24 桌面](artduo-frontend-2026-10-28/evidence/sculpture-calais-desktop-preview.png) 可见无扫描街景的加莱义民群像、独立展签和落地关系。源码的单次机会、原路线续接和状态保存也符合“偶遇”而非另开一套任务的目标（`sculpture-encounter.ts:19–43`、`use-sculpture-encounter.ts:25–41`）。本轮静态预览不证明正式触发及动态光照效果。

## 按优先级处理的问题

### L1 · P1：明确的“无人”愿望仍允许人物雕塑彩蛋

**场景与事实。** 用户输入“无人海景”或“我只想看没有人的海边”。源码 `packages/ui/src/experience/sculpture-encounter.ts:15–24` 仅匹配有限的排除表达。独立离线复现使用四件测试海景、一个加莱义民测试条目、`roll=.1`、`selection=0`，结果如下；没有创建线上展览：

| 输入 | permitsSculptureEncounter | 规划结果 |
| --- | --- | --- |
| 无人海景 | true | pending / calais |
| 我只想看没有人的海边 | true | pending / calais |
| 不要人物 | false | absent |
| 不看雕塑 | false | absent |

**影响（推断）。** “按我的观看愿望展开”是入口的核心承诺。若绘画遵守无人要求，侧厅却出现群像，观众会感到自己的边界被随机效果覆盖。问题在跨媒介的一致性，与加莱义民本身是否适合正式池无关。

**建议。** 彩蛋先复用/对齐已解析的必要题材、排除条件与媒介约束，合格后再执行既有 50% 机会与主题权重。保留 18 件正式池、一次机会和不重抽规则。

**建议验收。** “无人”“没有人”“不要人物”“不看雕塑”“只看油画”及对应英文表达均有确定性回归；含明确排除条件的展览无法因幸运抽签进入不相容的侧厅。普通开放愿望仍保持原概率和路线稳定性。

### L2 · P2 · 待验证风险：静观之后的导航再发现

**场景与事实。** 观看第一件后闲置 3.3 秒，再在画面中央移动鼠标 20px，下一件仍不可命中；到右边缘后恢复。见 [E10](artduo-frontend-2026-10-28/evidence/walk-desktop-idle.png)、[E11](artduo-frontend-2026-10-28/evidence/walk-desktop-edge.png) 与 O01。手机闲置后第一次点击画心，实际进入近看，可正常返回（E13/O02）；这不是触摸失效。源码 `use-idle-chrome.ts:17–39` 只在边缘、控件、点击或键盘等条件唤醒，`experience.css:350–355` 同时关闭淡出导航的命中。

**证据边界。** 中央鼠标移动不唤回、边缘移动唤回，是本项目此前已确认的静观策略；本轮实测符合该策略和实现。目前没有首次用户试验，不能将这一行为判作已证实的可用性故障。

**影响（未测推断）。** 首次观众若没有记住导航位置，可能需要探索边缘规则。画心点击的近看语义本身成立；是否会被误当作唤醒导航的动作，需要观察真实首次使用者，不能仅据本轮操作记录下结论。

**建议。** 先保留现有静观策略，验证是否需要一次性的克制提示，例如首件作品初次展示时提示“移到边缘继续”，不增加常驻工具栏。只有首次使用证据支持时，再决定提示的形式与时机。中央鼠标移动唤回可作为后续备选，但它改变已确认交互，需要另行设计决定，本报告不将其列为直接修复要求。

**建议验证。** 请首次使用者在静置观看后继续下一件，记录能否发现边缘控制、是否尝试无关动作及是否需要帮助，分别覆盖鼠标和真实触摸。先观察现有策略，再比较一次性提示；键盘当前保留控件的行为不得退化。

### L3 · P2：阅读路径的反馈与动作承诺没有完全衔接

**事实 A：展签打开前的等待。** E14 记录本次点击到 `dialog[open]` 为 **1436.2ms**；首个 rAF 时对话框尚未打开、触发器 `aria-busy=true`、`disabled=false`，状态文本为空。源码 `plaque.tsx:69–92` 确实等待参考图片 decode 后再显示对话框，仅以 `aria-busy` 标记触发器。本次未截等待中间帧，也不能断言所有参考资产已热，因此不把 1.4 秒当成普遍时延或宣称完全没有视觉反馈。

**事实 B：讲解还需要第二次决定。** [E14b 展签末尾](artduo-frontend-2026-10-28/evidence/reading-mobile-actions.png) 的“进入详细讲解”进入 [E15 独立资料页](artduo-frontend-2026-10-28/evidence/artwork-detail-mobile-top.png)。首屏仍是标题、作者和同一段短句；“生成这件作品的讲解”在本次文档 y=1062.22px 处，需向下滚动并再次点击，见 [E16](artduo-frontend-2026-10-28/evidence/artwork-detail-mobile-explanation.png)。本轮未点击生成。源码链路为 `plaque.tsx:115` → `apps/web/app/artwork/[id]/page.tsx:138–178` → `artwork-explanation-panel.tsx:67–70`。

**影响（推断）。** 观众已经主动选择阅读，此时等待但不知进度、或已经点“讲解”却还要寻找生成按钮，容易将注意力从作品转到操作判断。

**建议。** 图片准备期间给展签一个可见、克制的“正在打开”状态及明确取消/失败出口，保留避免空图首帧的目标。再统一动作名称与落点：若仍先去资料页，入口应明确为“更多作品资料”；若称为“详细讲解”，落点应立即呈现讲解内容或准备状态。按需生成可以保留，但应在承诺前说明，减少重复标题与短句对首屏的占用。

**建议验收。** 在正常及受限网络中，点击后可立即知道请求已接受，取消后无迟到弹层；图片失败仍可阅读文字。手机用户从讲解入口能预知下一步，并能直接找到其承诺的内容/状态；返回仍保留原展览与作品。

### L4 · P2：可达的路线支持页使用了另一套产品语言

**观察与源码。** [E21b 稳定态](artduo-frontend-2026-10-28/evidence/route-support-mobile-stable.png) 的路线支持页显示馆藏 release ID、总量、大标题“导览画廊”、带框输入、“策展意图”及另一组说明。资料页的“其他画廊路线”可以到这里（`apps/web/app/artwork/[id]/page.tsx:159–163`）；具体结构见 `apps/web/app/gallery/page.tsx:203–269`。稳定态的主按钮已增强，不能根据早期 E21 的红色按钮认定玻璃样式遗漏。

**影响（推断）。** 观众从“私人展览”支线进入“目录/策展工具”的心智模型，且需重新理解“观看愿望—策展意图—生成路线”三套表述。当前屏幕暴露的 release ID 不能帮助大多数观众决定下一步。

**建议。** 保留确有用途的路线支持能力，让支线沿用当前材料、输入与动作语言；将版本等运行信息移出默认观众界面。明确它是“重新选一组”还是“查看这次展览的其他路线”，并相应保留输入与返回位置。是否保留这条支线，可由后续产品决定；本评审不建议直接删除路由或破坏旧链接。

**建议验收。** 从资料页进入支线，用户能说清自己在修改当前观看还是创建新观看；默认视图不显示实现版本标记；仍可返回原作品。继续验证旧链接兼容。

### L5 · P2：手机设置的“鼠标”语言与实际开关范围不一致

**观察与源码。** [E17 手机设置](artduo-frontend-2026-10-28/evidence/settings-mobile.png) 和 [E18 展开设置](artduo-frontend-2026-10-28/evidence/settings-mobile-expanded.png) 在触摸环境里先显示已勾选的“画面随鼠标轻动”，下面又有“开启手机随动”。`walk.tsx:48,113–118` 将该鼠标偏好也用于禁用设备随动；`room-motion.ts:110` 在禁用时不提供手机入口。当前文字把一个通用随动总开关说成了鼠标专属选项。

**影响（推断）。** 手机用户可能以为随动已开，或关闭“鼠标”后无法理解为什么手机感应入口消失。这是设置语义与能力显露的问题，本轮没有证据说明真实手机传感器失效。

**建议。** 用与输入能力一致的语言，例如通用“画面轻动”，再将“开启手机感应”明确为单独授权动作；也可在触摸环境只展示相关选项。总偏好与权限状态要有可理解的关系，保持绘画、近看与雕塑的一致性。

**建议验收。** 鼠标、触摸、减少动态、感应未授权/允许/拒绝各状态均可辨认；关闭总随动后，手机入口的状态有解释；拒绝感应仍可静态观展。实体设备测试单列，不能用视口模拟替代。

## 概念与心流分析

| 阶段 | 应形成的感受 | 当前判断 |
| --- | --- | --- |
| 输入 | 我可以用一句话开始 | 留白和单主动作成立。可选的小幅文案改进：占位符兼顾“心情或想看的内容”；无需新增说明层。 |
| 序言 | 这次观看与我的愿望有关 | 观察到的文字以实际作品和画面线索开场，没有把本次中性水岸输入擅自解释成情绪诊断。提前制作纪念卡应继续处于次级位置。 |
| 展厅 | 我可以把注意力交给作品，也能决定何时向前 | 视觉主体明确，静观策略按已确认方式工作；L2 的首次导航再发现风险尚待用户验证。 |
| 阅读 | 我可以加深理解，再回到刚才的画 | 参考图、阅读文本稳定和位置恢复成立；L3 的等待与双重动作削弱连续性。 |
| 雕塑侧厅 | 偶然遇见另一种与此刻相容的作品 | 加莱义民的独立群像可承接人的经验；L1 需要保证偶遇仍尊重明确排除条件。50% 是合格展览的一次机会，不应成为覆盖愿望的理由。 |
| 结语 | 我可以停一下，再决定是否带走什么 | 末件作品与短句提供了收束；本轮未验证导出结果或手写服务实际完成。 |

这一体验的关键是“愿望被记住、观看可自主、阅读有连续性”。现有氛围足以支持这个目标；后续增加任何显著效果前，可先验证它是否帮助这三件事。

## 建议推进顺序

1. **先修复概念正确性：** 对齐绘画与彩蛋的硬性意图条件，加入 L1 的离线回归，保留现有概率、作品池和原路线。
2. **再梳理关键动作：** 处理 L3 的读取反馈、讲解名称与落点；对 L2 先做首次使用验证，保持已确认的静观策略，按证据决定是否加入一次性提示。中央移动唤回等策略变更需另行设计决定。
3. **统一支线与设备语言：** 处理 L4/L5；将默认界面、路线支持、资料和设置放到同一套产品语义里。
4. **最后补实机证据：** 软键盘、手机感应授权/拒绝、低端设备上的主链路录像与性能测量。当前只能给出需验证的范围，不能据静态图宣称全部通过。
