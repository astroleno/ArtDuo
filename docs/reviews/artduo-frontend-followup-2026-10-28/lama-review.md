## 总评

当前源码形成了清晰的“写一句 → 前言 → 观看 → 按需阅读 → 结语”结构。已观察到的首页与展厅在层级上保持克制：首页明暗稳定态居中、留白，只有一个主任务；空输入错误就地出现并回焦。桌面静观 / 边缘唤回与移动展厅都把作品放在主位，移动端画作、展签与底部导航没有互挡，资料页也可返回同一观看位置。应延续这条方向，无需重做首页或扩大常驻界面。

末件近看可关闭回展厅，经边缘控件进入结语，并能回看同一末件；独立 Calais 雕塑预览也已呈现可读模型。未发现已证实的 P1；四项 P2 集中在浏览器返回层级、明确媒介限定与失败状态的恢复 / 阅读布局。它们主要影响观展连续性与动作承诺，而非要求改变视觉语言。

## 应保留

1. **首页只给一个主任务。** 居中问句、透明细底线输入、单一“开始观展”按钮，避免把观看愿望改造成复杂筛选表。五秒问句在输入与页面隐藏时暂停，减少书写时的争抢（`packages/ui/src/experience/threshold.tsx:56`；`entry-question.tsx:34`）。柔和明暗背景与液态玻璃是已确认方向，不因通用风格禁令要求移除。
2. **静观与操作可以共存。** 画面上的普通鼠标移动不反复召回导航，边缘、明确控件、键盘与阅读状态负责召回或保留控制（`use-idle-chrome.ts:27`；`experience-shell.tsx:72`）。不建议增加常驻提示层、进度面板或自动换画。
3. **阅读保留作品参照的结构与文字兜底。** F09b 的正常阅读状态同时保留画作与文字；完整展签对解码失败设置五秒上限，F09 证明图片不可用时文字仍可阅读（`plaque.tsx:71`；`reading-image.ts:4`）。I10 确认更多作品资料页能返回原画作与路线，按需生成讲解的层级也应保留。参照图失败后的布局另见后文。
4. **雕塑是独立艺术品彩蛋。** 不将“无人海景”“不看人物”解释成排除雕塑；既定 18 件作品池、50% 单次机会与独立侧厅属于产品方向。F16 / I17 的独立 Calais 预览在 390×844 下模型为 `ready`、无横向溢出，雕塑与展台、展签的主次关系清楚。源码中侧厅提供“略过 / 继续观展”，应继续保持可退出而不强迫完成（`sculpture-room.tsx:118`）；独立预览不等于已验证随机侧厅全流程。
5. **设置与收尾保持按需。** F13b 的稳定设置面板把动效、声音和后续顺序收在一处，末件的顺序调整不可用状态与“本次已看完”一致。F15 / I15 / I16 确认“末件近看 → 返回展厅 → 看完了 / 进入结语 → 回看同一末件”路径成立，结语文案与可选保存动作分层清楚。无需让分享或手写制作成为完成观展的前置条件。

## 已确认问题

### P2 · 浏览器返回会越过阅读或放大层，直接离开展厅

**证据与复现：** 在触控模拟 390×844 下，从画作打开完整展签。I03 记录打开前后浏览器 history currentIndex 都为 2；I04 随后执行浏览器历史返回（`Page.navigateToHistoryEntry`），目标是 `/ArtDuo` 首页，阅读层与展厅同时离开。I07 在放大层也得到相同目的地。源码中展签仅通过 `showModal()` 与本地状态打开（[plaque.tsx:83](/Users/aitoshuu/Documents/GitHub/ArtDuo/packages/ui/src/experience/plaque.tsx:83)），放大层只设置本地展开状态（[image-lightbox.tsx:225](/Users/aitoshuu/Documents/GitHub/ArtDuo/packages/ui/src/immersive/image-lightbox.tsx:225)），路由只恢复展览位置（[experience-route-client.tsx:43](/Users/aitoshuu/Documents/GitHub/ArtDuo/apps/web/components/experience-route-client.tsx:43)）。

**影响：** 阅读层外观与“返回画作”动作都表达了临时进入资料的关系。习惯用浏览器返回收起这一层的观看者，却一次离开整段观看，破坏了“读完再看这件作品”的连续性。本次没有证据证明作品顺序或原句永久丢失，也未测试实体 Android 返回手势。

**建议：** 让临时阅读 / 放大层与浏览器历史保持一致，第一次返回关闭当前层并保留画作；继续维持展厅内部换画不逐件堆积历史的设计。

**验收：** 从任意画作打开完整展签或放大层后，浏览器返回先回同一画作、同一顺序；再次返回再遵循展览入口历史；层内关闭与 Escape 仍能关闭；浏览器前进不会产生重复层或改写当前作品。

### P2 · 明确限定媒介时，部分措辞仍允许进入雕塑侧厅

**证据与复现：** [sculpture-encounter.ts:15](/Users/aitoshuu/Documents/GitHub/ArtDuo/packages/ui/src/experience/sculpture-encounter.ts:15) 用独立正则判断是否允许侧厅，只覆盖绘画、画作、油画、水彩、风景、静物等词。本次直接调用当前 `permitsSculptureEncounter` 与 `planSculptureEncounter`，给定四件画、有效侧厅、`roll=0.1`，得到：

| 愿望原句 | 允许侧厅 | 计划状态 |
| --- | --- | --- |
| 只看版画 | 是 | `pending` |
| 仅限水墨 | 是 | `pending` |
| only watercolors | 是 | `pending` |
| 只看油画 | 否 | `absent` |
| 不要雕塑 | 否 | `absent` |
| 无人海景 | 是 | `pending`，符合既定方向 |

这里确认的是实际前端决策函数结果；尚未用线上真实随机观展复现。主检索已识别版画、水墨与英文水彩媒介（[viewing-intent.ts:67](/Users/aitoshuu/Documents/GitHub/ArtDuo/apps/web/lib/viewing-intent.ts:67)），侧厅的独立词表没有覆盖同一承诺。

**影响：** 使用者明确说“只看版画”后，仍可能被带入雕塑侧厅。问题不在彩蛋本身，而在媒介限定与实际呈现之间的承诺不一致。

**建议：** 让侧厅资格读取与观看愿望相同的媒介限定结果，或同步完整的限定语法；继续保留“画作人物排除不约束独立雕塑”的决定，避免扩大排除范围。

**验收：** 中文版画、水墨、素描等明确限定，以及英文对应句，在命中概率下均为 `absent`；“无人海景 / 不看人物”仍为可出现侧厅；明确同时愿意见到雕塑的句子不被一概排除。

### P2 · 放大换画的预备解码失败后，仍停留在“正在准备作品”

**证据与复现：** I12 仅让下一件 `smk-KMS4177` 的离 DOM 预备图解码拒绝，页面中的图片解码照常。从第一件放大层点“下一幅”，观察 5200 毫秒后，地址已到第二件，但可见作品与署名仍为第一件；F12 显示“正在准备作品”，前后切换均禁用。关闭按钮仍可用，I14 恢复注入并用 Escape 退出。此为受控失败分支复现，不代表自然生产故障，也不推断发生频率。

**影响：** 保留旧画与旧署名是正确的连续性保护；缺口是已经失败后仍承诺正在准备，观看者无法在本层重试或回到上一件，只能退出放大层处理。

**源码依据：** [image-lightbox.tsx:141](/Users/aitoshuu/Documents/GitHub/ArtDuo/packages/ui/src/immersive/image-lightbox.tsx:141) 在新预览解码失败后直接返回，没有切换失败状态；`103` 行的作品身份差异一直存在，`292` 行继续禁止切换；[immersive-detail-stage.tsx:531](/Users/aitoshuu/Documents/GitHub/ArtDuo/packages/ui/src/immersive/immersive-detail-stage.tsx:531) 仅显示准备提示。

**建议：** 将“准备中”与“准备失败”区分。失败后继续保留当前可读作品，提供明确的重试或返回上一件动作，并确保实际可见作品与恢复后的路线位置一致。

**验收：** 预备解码明确拒绝后，出现失败说明及可执行的恢复动作；成功重试后作品与署名一起切换；取消后保留原画及对应位置；Escape / 层内关闭始终可用。正常切换仍避免新署名提前覆盖旧画。

### P2 · 移动阅读的图片失败态仍占据约 300 像素，压缩可读资料

**证据与复现：** F09（`evidence/reading-mobile.png`）出现“图片暂不可用，资料仍可阅读”。390×844 视口里，空图片区约从 y=162 延伸到 y=463，占 301 像素，底部可滚动的文字区只能先呈现标题、作者、短段落与第一行资料。首次失败的根因未记录；I08 / I09 与 F09b 随后正常载入同一参照图（1280×1019，资源 200），因此这里仅评审失败状态的布局，不声称图片稳定加载失败。

**影响：** 降级后主要内容已经变成文字，空图片区却仍保持成功态的视觉权重，长标题、正文与资料被挤在较小的下半区。

**建议：** 保留正常状态的图文参照结构。图片确认失败后，将该区域收为紧凑状态提示，优先把高度还给文字；若可复用当前画作预览，也可继续提供可读的静态参照。

**源码依据：** [experience.css:468](/Users/aitoshuu/Documents/GitHub/ArtDuo/packages/ui/src/experience/experience.css:468) 将移动阅读图像行设为 `minmax(130px, min(38dvh, 300px))`；[plaque.tsx:99](/Users/aitoshuu/Documents/GitHub/ArtDuo/packages/ui/src/experience/plaque.tsx:99) 在失败后隐藏图片并显示文字，但没有改变该行占用。

**验收：** 在相同 390×844 视口主动触发图片失败后，提示清晰、关闭入口仍可用，空图片区不再保留成功态的 300 像素占用；长标题、正文与资料可在更大的连续阅读区内访问；正常载入的作品参照图不受影响。
