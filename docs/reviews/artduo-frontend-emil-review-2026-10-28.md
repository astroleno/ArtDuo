## 范围、方法与证据边界

使用 `emil` 路由下的 `emil-design-eng`，重点检查界面细节如何累积成完整体验：动作是否兑现承诺、反馈是否及时、常用操作是否被动效拖慢、分支是否仍属于同一场展览。没有读取另一位评审者的报告，也没有修改应用代码。

主线程统一采集线上中立证据，本评审独立查看截图、操作记录并核对源码。[证据清单](artduo-frontend-2026-10-28/evidence/manifest.json)记录 URL、状态与计时。已实际查看入口明暗态与错误态、序言、提前备卡面板、展厅到达/静置/边缘唤回、手机首触近看、完整展签、资料页、设置、结语、路线辅助页及加莱义民独立预览截图。关键图在下文直接链接；入口、路线辅助页和结语优先采用补采的稳定态证据，不将玻璃增强前的按钮外观当作最终设计。

本轮使用 1440×900 与 390×844 浏览器视口；手机路径包含触摸模拟，并非实体手机测试。观展内容来自同一份已保存的六件作品展览回放；结语通过该展览的深链接检查，不等于本轮逐件走完所有中间状态。没有提交新策展、详细讲解或手写生成任务，也没有下载分享图。

以下分别标注「实测」「源码事实」「待验证」。单次点击计时不代表平均性能、冷启动性能或服务承诺；截图不证明帧率。首次自由输入的策展质量、慢网完整旅程、实体设备感应、真实听感及自然雕塑彩蛋均不在本轮实测结论内。截图中的浏览器扩展魔棒叠层不计入 ArtDuo 界面。

## 总体判断

主线已具有清晰的私人观展感：一句愿望进入、简短序言、作品居中、可选阅读、最后以作品和寄语收拢。下一轮更有价值的工作是修平几个动作交接处，而不是重做入口或增加视觉装饰。

建议保留以下已经成立的设计：

- **入口的空白与单一任务。** [浅色桌面](artduo-frontend-2026-10-28/evidence/entry-desktop-light.png)、[浅色手机稳定态](artduo-frontend-2026-10-28/evidence/entry-mobile-light-stable.png)、[深色手机](artduo-frontend-2026-10-28/evidence/entry-mobile-dark.png)都有明确的问句、细底线输入和一个开始动作。不要补回大段产品解释、卡片、作品拼贴或斜光。错误在输入下就地显示，也应保留。
- **五秒翻牌服务于入场前的邀请。** `entry-question.tsx:34–49` 负责五秒间隔、减少动态和页面可见性；`threshold.tsx:57` 在输入聚焦或提交时暂停后续轮换。用户已确认这一节奏，不应套用工作台的高频动效规则将其取消。
- **观看时让控制层安静下来。** E10/O01 记录画作中央移动不唤回导航，E11 记录边缘唤回；这符合已确认的观看手势分工。设置仍可触达。E13/O02 的手机首次触画进入近看并能返回，没有证据支持“触摸失效”的判断。
- **阅读保留完整作品参照。** [手机阅读层](artduo-frontend-2026-10-28/evidence/reading-mobile.png)保持画作与独立滚动正文；源码 `plaque.tsx:69–90` 等待真实图片解码再打开，`use-stable-narrative.ts:6–16` 稳住已读文字。方向正确，需要改善的是等候反馈。
- **结尾仍让作品承担情绪。** [桌面结语稳定态](artduo-frontend-2026-10-28/evidence/closing-desktop-stable.png)、[手机结语稳定态](artduo-frontend-2026-10-28/evidence/closing-mobile-stable.png)保留末件作品、署名、短寄语及回看；保存和手写都是可选分支，没有强制分享。

### EML-01 · 展签的等待需要可感知反馈

**触发场景：** 用户在手机观看一件作品后点小展签，希望读一两句说明。

**证据：实测与源码事实。** E14 记录从点击到 `dialog[open]` 为 **1436.2ms**；首个 `requestAnimationFrame` 时仍未打开，触发器 `aria-busy=true`、未禁用，记录到的 status 文本为空。同一作品此前已近看，但无法据此确认所有素材和解码均已热。没有等待中间帧截图，因此不宣称整个 1.44 秒绝对没有任何视觉变化。

代码明确在 `image.decode()` 完成后才 `showModal()`；触发按钮的等待状态仅写入 `aria-busy`，没有等待文案或专门的可见状态。见 [plaque.tsx:69–98](../../packages/ui/src/experience/plaque.tsx#L69-L98) 与 [展签就绪截图 E14](artduo-frontend-2026-10-28/evidence/reading-mobile.png)。

**用户影响：** 图像留在眼前是好的，但缺少持续的接收反馈会诱发第二次点击。当前第二次点击会触发同一个切换动作，容易把用户刚才的打开意图取消；这属于可预见风险，本轮未以连点实测证实其发生频率。

**建议：** 点击后立即保留轻微的选中/按下状态；等待超过约 150–200ms 时，在既有展签范围显示“正在打开…”等短提示。继续保留画面、取消能力及真实图片就绪后再展示的策略，不换成遮画的大加载层。

**验收：** 热图、未完成解码、图片失败和打开后立即取消四种状态均有明确反馈；等待过程中能取消，且取消后不会迟到打开。以页面时间戳检查接收反馈，不把网络准备时间混入动画时长。

### EML-02 · “讲解”的动作承诺与落点不一致

**触发场景：** 用户读完展签，点击“进入详细讲解”。

**证据：实测与源码事实。** [E14b](artduo-frontend-2026-10-28/evidence/reading-mobile-actions.png)显示该动作；[E15](artduo-frontend-2026-10-28/evidence/artwork-detail-mobile-top.png)为实际资料页落点，[E16](artduo-frontend-2026-10-28/evidence/artwork-detail-mobile-explanation.png)才显示“按需讲解 / 生成这件作品的讲解”。生成按钮的文档纵坐标约 **1062px**，本轮视口高 **844px**。本轮未点击生成，不评价讲解响应质量与耗时。

来源为 [plaque.tsx:114–119](../../packages/ui/src/experience/plaque.tsx#L114-L119)、[experience-route-client.tsx:62–76](../../apps/web/components/experience-route-client.tsx#L62-L76)、[artwork-explanation-panel.tsx:67–80](../../apps/web/components/artwork-explanation-panel.tsx#L67-L80)。

**用户影响：** 已从作品转入阅读，又从阅读离开到新页面，还要滚动并作一次生成决定。“进入讲解”实际兑现为“去一个可再请求讲解的地方”，打断了刚形成的好奇心。

**建议：** 优先将当前跳转准确命名为“查看作品资料”，保持用户明确点击才生成。若继续使用“详细讲解”作为入口名称，就应把落点对齐讲解区并提前说明按需准备；不要为了少一次点击而自动发起额外模型请求。现有“返回刚才的位置”实际恢复同一展览和作品，应保留。

**验收：** 手机进入该分支后，用户无需寻找即可辨认“当前是资料”及“讲解尚未请求”；动作名称、落点标题和后续按钮互相吻合。返回保留同一 `curationId`、作品与路线。

### EML-03 · 路线偏好要准确表达“先后”，而不是“增减”

**触发场景：** 用户打开设置的“本次展览与路线”，希望多看喜欢的类型或换一种题材。

**证据：实测界面与源码事实。** [E18](artduo-frontend-2026-10-28/evidence/settings-mobile-expanded.png)显示“调整只影响还没走到的作品”和四个偏好动作。`applyPendingPreference()` 保留已走前缀、只对同一批未看作品排序，没有新增、删除或替换作品。见 [viewing-controls.tsx:9–24](../../packages/ui/src/experience/viewing-controls.tsx#L9-L24)、[viewing-session.ts:129–146](../../packages/ui/src/experience/viewing-session.ts#L129-L146)。本轮未选择偏好，不把源码推导记为一次真实重排试验。

**用户影响：** “多看”通常承诺更多数量，“换一种题材”容易承诺新选集；目前控制实际能做到的是先看哪些。情绪驱动产品尤其需要避免让人误以为系统没有听懂第二次表达。

**建议：** 保留冻结选集和不改已看作品的设计。将文案改为“先看更安静的作品 / 先看相似作品 / 先看不同题材 / 恢复原有顺序”，辅助句明确“只调整本次展览尚未看过的顺序”。不增加前台选项，也不借评审改为实时重新策展。

**验收：** 四个动作及成功/无需调整/已到末段提示均使用顺序语义；操作前后作品 ID 集合一致，已看前缀一致，实际可调整的尾部与提示吻合。

### EML-04 · 近看分支需要回到同一套交互工艺

**触发场景：** 连续几件作品之间反复近看、返回，或在手机近看中开启随动。

**证据：截图与源码事实。** [E13](artduo-frontend-2026-10-28/evidence/walk-mobile-first-tap.png)顶部的近看操作是圆胶囊；已确认的其他操作采用 LuBirth 玻璃样式。玻璃增强选择器包含近看前后导航，却没有 `.immersive-detail-close` 与 `.immersive-detail-motion-toggle`。手机随动按钮 CSS 最小高仍为 36px，手机返回按钮已是 44px，应分别判断。见 [glass-buttons.ts:3–15](../../packages/ui/src/glass/glass-buttons.ts#L3-L15)、[globals.css:3431–3459](../../apps/web/app/globals.css#L3431-L3459)。

另一个重复操作成本是：近看进入固定 720ms，`phase` 未进入 `open` 时前后导航禁用；返回固定等待 520ms 才执行 `onClose()`。见 [immersive-detail-stage.tsx:42–43](../../packages/ui/src/immersive/immersive-detail-stage.tsx#L42-L43)、[104–117](../../packages/ui/src/immersive/immersive-detail-stage.tsx#L104-L117)、[530–545](../../packages/ui/src/immersive/immersive-detail-stage.tsx#L530-L545)。这些是代码定时值，本轮没有测量实际合成帧率或退出端到端耗时。

**用户影响：** 近看是主线中的高频分支。不同材质、不同触区和较长的重复退出会让“靠近这件作品”变成“进入另一个模式”。

**建议：** 复用现有玻璃按钮规则，触区至少 44px，保留图像和空间过渡。首次进入可以舒展，不必机械压缩所有艺术过渡；重复返回建议压到约 160–220ms，键盘 Escape 优先立即恢复可操作状态，避免反复等待整段退场动画。不要加入更强弹跳或更大旋转。

**验收：** 桌面与手机的近看返回/随动/前后按钮属于同一材质规则，触区达标且不遮作品；连续进入/退出与快速 Escape 不丢焦点、不串图、不触发晚到关闭。减少动态模式保持静态、可退出。

### EML-05 · 恢复路径与路线辅助页仍带着另一套产品语言

**触发场景：** 用户从资料页点“其他画廊路线”，或在空结果/异常恢复中选择路线辅助入口。

**证据：实测辅助页与源码事实。** [E21b 稳定态](artduo-frontend-2026-10-28/evidence/route-support-mobile-stable.png)重新出现“导览画廊”“策展意图”“生成观展路线”、馆藏版本和作品数量。主按钮已完成玻璃增强，早期 E21 的红色按钮不计为常态样式缺陷。空结果源码仍将入口写为“查看经典路线”；异常边界提供“返回画廊”。见 [experience-shell.tsx:275–285](../../packages/ui/src/experience/experience-shell.tsx#L275-L285)、[immersive/error.tsx:10–15](../../apps/web/app/gallery/%5Bid%5D/immersive/error.tsx#L10-L15)、[artwork/page.tsx:159–164](../../apps/web/app/artwork/%5Bid%5D/page.tsx#L159-L164)、[gallery/page.tsx:202–274](../../apps/web/app/gallery/page.tsx#L202-L274)。本轮直接打开辅助页，没有人为制造线上异常或空结果。

**用户影响：** 极简入口已经建立“写一句话就为我开一场展览”的约定，辅助页却要求用户再次进入策展表单，认识“路线”和馆藏版本。这里并不是旧展厅渲染器重新启用，而是仍在提供服务的辅助页未完成概念收口。

**建议：** 常规恢复优先回到保留原句的新版入口；将“经典路线”改成用户能理解的当前能力名称。确需保留辅助页时，沿用同一输入语义和克制层级，把馆藏版本等信息留在按需资料中，说明是否会重新生成展览。保留 URL 兼容与馆藏支持能力，无需删除底层功能。

**验收：** 空结果、失效展览链接、异常重试及资料页返回各有清楚去向；恢复路径保存原句，重新策展的后果明确。前台不再用“经典”暗示另有旧版体验，辅助页也不成为第二个默认入口。

## 概念一致性与心流分析

| 阶段 | 已成立的体验 | 还应守住的约定 |
| --- | --- | --- |
| 入口 | 抽象问句让人表达；明暗和玻璃表面足够克制 | 问句是邀请，不是情绪诊断；不要补回多层产品说明 |
| 序言 | 本次回放的文案围绕真实画面中的屋顶、海湾、树冠与天空，进入动作明确 | 不以文案生成阻挡观画；提前备卡保持自选，不能自动制作 |
| 观看 | 作品居中、背景静止、控制层闲置后退出，保留用户自己推进的节奏 | 视差和光只协助空间感；导航不靠持续动画争夺注意力 |
| 阅读与近看 | 画作参照、稳定文字、原位置返回支撑连续观看 | 等待有回应；分支动作说到做到；常用退出比入场仪式更快 |
| 路线调整 | 冻结选集与已看前缀被尊重 | “我的选择有效”首先要求文案准确表达可调整的范围 |
| 雕塑侧厅 | 源码维持 50% 机会、最多一次、可略过、回到原绘画路线 | 不把概率彩蛋变成每次必须出现的任务，不把人物一概神化 |
| 结语 | 以末件作品与短句结束，允许回看或保存 | 不把收尾扩张为功能清单、强制分享或另一轮问卷 |

雕塑彩蛋这一项是架构检查，不是本轮自然触发结果：`sculpture-encounter.ts:4、20–43` 和 `use-sculpture-encounter.ts:20–41` 将机会及状态固定于展览；`experience-shell.tsx:296–300` 提供继续接口。[加莱义民手机预览 E23](artduo-frontend-2026-10-28/evidence/sculpture-calais-mobile-preview.png)与[桌面预览 E24](artduo-frontend-2026-10-28/evidence/sculpture-calais-desktop-preview.png)证明此独立预览能呈现无原始环境的群像及作品展签；不证明正式彩蛋触发率、全池构图或实机性能。名作与人民史观是已确认的内容约束，本评审不提出换回神性主导的选池，也未独立复核全部十八件模型、介绍和渲染。

入口的明暗与无衬线、展厅的纸色衬线、阅读层的浅色纸面可以作为空间转换保留；一致性不意味着所有背景必须同色。真正影响一致性的，是动作含义和响应规则能否一路延续。

## 建议执行顺序与补验

1. 先处理 **EML-01**：给已经合理的图片就绪门槛补上接收反馈和取消回归，避免人等待时反复试探。
2. 同一轮修正 **EML-02 / EML-03** 的动作与顺序文案，保持按需请求和冻结展览架构。
3. 统一 **EML-04** 的近看控件和重复退出节奏，以连续五件作品的进入/返回检查手感，不只欣赏一次入场动画。
4. 收口 **EML-05**，专门验收空结果、错误、辅助路线和详情返回；不必重做已成立的首页。
