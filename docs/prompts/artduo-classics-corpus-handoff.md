# ArtDuo 经典画作数据整理任务

请为 ArtDuo 整理一套可核验、可接入现有数据管线的经典画作候选数据。我会把你的交付交给负责前端与接入的 agent。当前任务是数据研究、样本整理和接口映射，不是修改产品界面或发布新馆藏。

## 项目背景与先读资料

ArtDuo 根据用户的一句心情、场景或观看愿望，从版本化的本地馆藏中选出作品，在沉浸式展厅中展示；详细讲解按需生成。正式应用是 `apps/web`，`experience/` 是视觉参照和 mock 原型，不是生产数据源。

先阅读仓库内这些文件，以实际代码为准：

- `docs/specs/artduo-v2-local-corpus-and-media-schema.md`
- `docs/specs/artduo-v2-shared-contracts-and-api.md`
- `packages/contracts/src/artwork.ts`、`packages/contracts/src/corpus.ts`
- `packages/corpus/src/release-loader.ts`
- `apps/pipeline/src/release-artifact.ts` 及现有候选采集、metadata、search、media、release 构建入口
- `apps/web/lib/release-catalog.ts`、`apps/web/lib/experience-adapter.ts`
- `docs/reviews/artduo-experience-integration-acceptance.md` 的内容相关性记录

## 研究目标

优先补充适合挂画展示的中外经典平面画作：油画、水彩、素描、版画、中国书画、壁画的清晰正面图像。当前首要问题是展览混入了器物、雕塑、建筑构件和照片；这些不能作为本次画作候选。古籍只在与画作有具体关系时作为解释证据，不扩展成独立古籍全文库，也不把普通扫描书页、装帧、器物或建筑照片当成绘画。

每件候选标明作品类型，并给出馆方 classification/objectName/medium 等原始证据；审核图像主角确为画作。区分画作本身与画作拍摄环境；完整长卷/册页可保留，不以极端宽高比为理由裁坏作品。题名包含“花瓶”“建筑”“雕塑”不构成排除依据——画中画了花瓶仍然是画。标题中出现 painting 或 medium 中出现 painted 也不能单独证明是一幅画。

区分“可展示的作品图像”与“供解释引用的文本证据”，不要把纯文本硬塞成图片作品，也不要凭主题相近就宣称某件画作出自某部典籍。文本证据只需随有实际关联的候选提供，不要求为了凑数量给每幅画配一句诗。

优先使用博物馆、图书馆、大学、档案馆等机构的官方藏品页、开放 API、IIIF、可下载目录和版本清楚的古籍数据库。先交付能够逐条检查的小样本与扩充路径，不以条目数量替代质量，不默认进行大规模下载或付费调用。

## 每条数据必须具备

1. 稳定内部 ID、机构原始 ID、来源机构、官方详情页、实际获取日期；API/IIIF 地址在来源提供时记录。
2. 作品原名、经核验的中文名（无可靠译名则保留原名）、作者/归属、时代/年代、媒材、尺寸、文化语境。未知字段明确为空，不编造。
3. 图像预览与原图地址、实测宽高、文件类型、可获取性、内容完整性；长卷/册页/书页记录顺序与所属集合，避免只截局部却当成全作。存在下载许可时可保存少量验证样本，记录校验值。
4. 逐项记录图像、元数据、古籍原文、现代译文/校注各自的权利声明与来源链接。无法确认复用范围的进入待核验区；不能以“古代作品”推定现代影像或译注可任意使用。
5. 引文记录书名、篇/卷/章、版本或整理者、页码/稳定定位、原文与出处链接；区分 OCR 原文、人工校对、现代翻译和你的概括。不要生成假引文。给出图像作品与文本证据的关联类型、依据及置信度；仅主题类比须明确标注。
6. 面向检索的中文关键词、英文同义词、客观题材、色彩/构图/空间线索，以及单独的情绪标签。事实、视觉观察、解释和模型推断分别记录。血腥、战争、灾难、死亡等内容标明可见线索与出处，不能将这些作品只因“低落”就当作舒缓推荐。
7. 一句克制的展签短文，指出具体可见内容或已知事实；不要“疗愈你的灵魂”“与你共鸣”等套话，不伪造作者意图。保留原始文本，清洗结果可追溯。

## 数据流与交付

在独立的候选目录中交付，不覆盖已有 release，也不改动前端、检索排序或共享契约：

- `README.md`：资料范围、实际来源、获取方式、重现步骤、规模/调用成本、已知限制及待决定事项。
- `sources.csv`：逐来源列出访问方式、稳定 ID、字段覆盖、图像质量、权利依据、限流/增量更新方式、推荐与排除理由。
- `artwork-candidates.jsonl`：图像作品候选；分清原始值、清洗值、翻译值与出处。
- `text-evidence.jsonl`：典籍文本与定位；保留独立文本身份，不伪装成 ArtworkRecord。
- `artwork-text-links.jsonl`：作品与文本的有依据关联，允许没有关联。
- `field-mapping.md`：逐字段映射到当前 ArtworkRecord、metadata/search/media/release 产物，列出当前无法表达的权利/引文/集合字段及建议的 sidecar 结构。当前 source 枚举只有 `met`/`custom`；不得冒用 `met` 或自行扩展契约。`custom` 候选仍须保留实际机构来源。
- `validation-report.md`：可重现的链接/图像检查、缺失率、重复记录、权利不明项、OCR/译名错误，以及人工抽查样本。不能把未验证项计作通过。

用一组真实样本演示“官方来源 → 原始记录 → 清洗/去重 → 字段映射 → 检索索引候选 → 展签与可引用证据”的完整链路。分别给出可直接使用、需补证、当前不适合接入三类结果。说明新增来源如何保持稳定 ID、幂等更新和不可变 release；不要自动构建或切换正式发布版本。

## 内容验收

用以下观看愿望检查候选覆盖，每项展示若干实际条目及来源，不用虚构打分：疲惫想安静、低落想缓一缓、明亮有活力、花瓶静物与建筑题材绘画、山水/树木/水面、中文夹杂 tired/quiet/moonlight/hope。说明哪些是明确题材匹配，哪些只是情绪类比，哪里仍缺数据；推荐结果必须仍是平面画作，不能用陶瓷实物或建筑照片填满数量。

最后给接入 agent 一份简短交接：可以直接使用的文件、字段适配工作、尚缺的权利或证据、必须由用户决定的范围问题。任何模型生成内容必须标明，不能冒充馆方说明、古籍原文或真实深度图。
